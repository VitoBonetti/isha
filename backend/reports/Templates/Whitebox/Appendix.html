6.3. Appendix - Steps for an efficient fix validation (retest)

Our shared goal is to verify and close security findings as quickly and efficiently as possible. When you mark a vulnerability as "solved," our retest process begins. Here’s how you can help make that process seamless and fast.

1. Retest Readiness

To validate your fix, we need the same access we had during the original test. Delays in access are the #1 reason for delays in closing findings.
  • Test accounts: Ensure test accounts remain functional or provide new ones
  • Network Access: If not internet facing, help us with the connectivity whenever possible
  • Notify changes: If the application URL or environment changes, please let us know
A ready environment means we can start validating immediately. A blocked environment means delays for everyone.

2. Provide Clear Fix Context & Evidence

When you mark a finding as "solved" in the platform, tell us about the fix. The context is invaluable.
  • Add a Comment: In the vulnerability ticket, briefly describe the change you made.
    Example: "We have implemented server-side validation on the user profile form to sanitize input and prevent XSS."
  • Attach Evidence: For straightforward changes and fixes, a screenshot can significantly speed up validation.
    Good examples: A screenshot showing a security header has been enabled, a directory listing has been disabled, or a debug mode has been turned off.
